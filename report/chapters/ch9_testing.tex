\chapter{Testing, Reproducibility and Performance}\label{ch:testing}

\section{Testing strategy}
The backend has 110 test modules in \code{backend/\allowbreak tests} (895 test items collected by \code{pytest}, 830 \code{def test\_} functions by a plain text count; parametrised tests account for the difference). The worker package has nine tests and the frontend has 29 test files. Continuous integration (\code{.github/\allowbreak workflows/\allowbreak ci.yml}) runs on pushes to \code{Main} and on pull requests: backend \code{ruff} and \code{pytest} against a Postgres service container, worker \code{ruff} and \code{pytest} with a slim install, and the frontend tests, type-check and build. We did not generate a coverage report for this thesis, so we give no coverage percentage.

The tests are grouped by area: the FRIES scorer against frozen vectors in \code{shared/\allowbreak scoring/\allowbreak fixtures}; fairness statistics and the decision order of Table~\ref{tab:fairrule}; robustness, safety and the prediction gate; artifact integrity, the tamper demonstration and the disclosure-gap separation split; the O/S/D engines, including the frozen v4 anchors (\code{check\_frozen}) and the LLM fallback; the LLM comparison and independent review harnesses (packet building, leakage checks, hash matching, parsing, agreement categories); and the pipeline and API lifecycle.

\paragraph{Test-driven where it counted.} For the round-3 changes we wrote the failing test first, watched it fail, implemented, and ran the whole suite. Some tests found real mistakes in our own designs before any experiment: the leakage test caught model names in packet source paths, and a unit test caught a risk-present rule that returned UNCERTAIN for a triggered integrity risk whenever an unrelated gate had also failed (a correction made before any packet was built, and recorded in the LLM comparison pre-registration). The engineering issues in Table~\ref{tab:bugs} each have a regression test.

\paragraph{What the tests do not cover.} Most probe tests use injected fake backends, so they check logic and contracts, not behaviour on real checkpoints. The controlled experiments are the real-weight tests, and they found problems the unit tests could not (the label-mapping failure of Section~\ref{sec:pilot}).

\section{Reproducibility}
\begin{itemize}
\item \textbf{Pinned inputs.} Civil Comments is pinned to a dataset revision; Hub models in the external audit are pinned to immutable revision SHAs that were re-resolved against the Hub before use; the selection file was written before any run; weight sha256 values are recorded.
\item \textbf{Seeds and determinism.} Probes take a seed; Fairness, Robustness and behavioural Safety evidence was identical across repeated runs in every experiment (zero standard deviation over five runs; the fairness confirmation run and severity sweeps identical on repeats). A second data preparation with the same seed (fairness confirmation) is byte-identical, including \code{ground\_truth.json}.
\item \textbf{Frozen, hashed results.} Result folders are never edited after the fact; the external audit folders carry a \code{SHA256SUMS} file; deviations are recorded with their timing (Table~\ref{tab:posthoc}).
\item \textbf{Replayable analyses.} LLM comparison recomputes all numbers from stored provider responses with \code{--replay}; disclosure-gap separation replays offline from stored inputs; the human analysis script regenerates its report byte for byte from the raw export.
\item \textbf{What is not reproducible.} LLM answers from live providers (quota, availability, and provider changes mean a re-run would differ); one run per Hub model; weights of the controlled models are not committed (they are reproducible from seeds, and their hashes are recorded).
\end{itemize}
