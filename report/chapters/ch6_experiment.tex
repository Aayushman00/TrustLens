\chapter{Experimental Design}\label{ch:method}

\section{Working principles}
The experiments in this chapter were designed under a few rules that we set after the first round of results embarrassed us a little. We wrote them in the instructions for the second round and held to them for the rest of the project.
\begin{itemize}
\item \textbf{Result folders are frozen.} A new run goes into a new folder. Earlier folders (\code{eval\_results*}, \code{final\_20261002\_*}, \code{sweep\_20261002\_*}, \code{hub\_final\_*}, and the v8 independent review and Hub folders) are never edited. When the methodology changed to v9 we re-ran into new \code{v9} and \code{v9r} folders.
\item \textbf{Declare before running.} For score calibration, LLM comparison, fairness confirmation, severity sweeps and independent review the plan document in \code{docs/\allowbreak superpowers/\allowbreak plans/\allowbreak } states the hypotheses or comparison rules and says it was written before the run (for fairness confirmation the freeze is the commit \code{8f009fb}). Deviations are recorded in the same document with a note saying when they were decided.
\item \textbf{No tuning on the data that exposed a problem.} Any change that alters a score, band, flag or prompt bumps \code{CURRENT\_METHODOLOGY\_VERSION} or \code{PROMPT\_VERSION}. A mapping change must be fitted on separate data and then evaluated on the frozen suite.
\item \textbf{Negative results are results.} A failed hypothesis is reported as failed. If a rule should change, it becomes a new version with new data.
\item \textbf{Evidence reviewers are not ground truth.} Humans and LLMs that read evidence packets are called \emph{evidence reviewers}. Disagreement with TrustLens is described and categorised, not adjudicated.
\item \textbf{Keep Claude results separate.} Where we used Claude as an additional independent LLM evaluator, its answers live in separate supplementary folders and are never merged into the official LLM comparison or independent review results.
\end{itemize}

\section{Common setup}
\textbf{Task and data.} All behavioural experiments use binary toxicity classification on English comments. The evaluation set is a 3\,000-row sample of the Civil Comments \code{test} split \cite{borkan2019}, pinned to dataset revision \code{f2970eb3\ldots}, with a 20\% positive rate (toxicity $\ge$0.5). The sensitive attribute \code{identity\_ref} is 1 when the row has \code{identity\_attack}$>0.0001$; the \code{severe} marker is 1 when \code{severe\_toxicity}$>0.0001$. The suite eval set has 282 severe toxic rows and a label-rate gap of 0.505 between the identity groups, a fact that matters for fairness (Section~\ref{sec:l4}). A fresh eval set under data seed 20261003 (fairness confirmation) has 260 severe toxic rows and group sizes 2\,500 and 500.

\textbf{Models.} Controlled models are fine-tuned from \code{bert-base-uncased} \cite{devlin2019}: three epochs, learning rate $2\times10^{-5}$, batch 16, weight decay 0.01, maximum length 128, seed 42 unless noted. Each fine-tuning took about 160 seconds on the RTX 4060 laptop GPU (the manifests record 160.4--178.3\,s). Each checkpoint is a float32 BERT-base model.

\textbf{Reference models.} \code{unitary/\allowbreak toxic-bert} at revision \code{4d6c22e7\ldots} is the real-world reference. It has six sigmoid outputs; TrustLens decides with an argmax over softmax, which cannot express ``toxic versus not toxic'' on that head. We therefore also built \code{reference\_toxicbert\_2label} (\code{convert\_reference\_2label.py}): encoder weights unchanged, new head with $\text{logit}_0=0$ and $\text{logit}_1=z_{\text{toxic}}$, so $P_1=\sigma(z_{\text{toxic}})$ and the argmax picks ``toxic'' exactly when the original output exceeds 0.5. A check on four sentences gave a maximum probability difference of $9.5\times10^{-4}$. Predictions near the boundary can differ from the original. We call both \emph{reference} models because they are established public releases, not because we have proof of their quality, and we show in Chapter~\ref{ch:results} that the 2-label reference has its own measurable disparity.

\textbf{Environment.} Docker Compose stack (\code{api}, \code{worker}) on a laptop with an RTX 4060 (8\,GB), CUDA, float32, batch size 8, sequential execution to stay inside RAM and VRAM.

\subsection{Defect severity levels}
To test whether TrustLens responds in proportion to severity (RQ2), we trained six more models on the same clean slice with the same hyperparameters, changing only the flip rate, with nested flips (a lower rate is a subset of a higher one). Fairness levels were 0 (V3 weights), 0.2, 0.4 (V1), 0.7, 1.0; Safety levels 0 (V3), 0.25, 0.5 (V5), 0.75, 1.0.

\subsection{Detection rules (frozen before the runs)}
\code{ground\_truth.json} was written before the final runs and fixes two rules.
\begin{description}[leftmargin=1.2em]
\item[Score level.] A dimension is \emph{flagged} for a model if its mean dimension score over the repeat runs lies below the mean of \code{reference\_toxicbert\_2label} by more than $\max(1.0,\,2\times\text{pooled sample std})$. A dimension without a score is \emph{abstained}, not flagged.
\item[Evidence level.] A dimension is flagged if, in a majority of runs, the probe reports a non-empty \code{risks\_triggered} or \code{aspect\_scoring} in \{\code{risk\_detected}, \code{scored\_risk}\}; for Safety also if the Wilson lower bound of the severe FNR exceeds the control's point estimate.
\end{description}
Detection means the injected dimension is flagged; a false positive is a flagged dimension that was not injected. Controls are excluded from the counts and reported through a \emph{control flag rate}. The \code{controls} field was added to the file after the runs, from existing role entries, and we say so wherever the numbers are used.

\subsection{Repeat runs and the frozen LLM prompt}
The main suite was run five times per model (nine models), the sweep three times per level. The LLM configuration was frozen in \code{llm\_freeze.json}: Groq \code{openai/\allowbreak gpt-oss-120b}, temperature 0.2, prompt \code{llm\_v1}; other providers were blanked by \code{docker-compose.experiment.yml}. Methodology version for this suite: \code{v3-hardening-2026}. The suite ran on the image built at experiment start, before the engineering fixes in Table~\ref{tab:bugs}; the git commit is recorded in each run folder.

\section{Severity-sweep experiment}\label{sec:l6m}
The severity-sweep driver runs the production \code{RobustnessProbe} and \code{SafetyProbe} in-process on the fairness confirmation eval set, with no LLM and no API. The design and the monotonicity definitions were written before the run.
\begin{itemize}
\item \textbf{Robustness sweep:} one knob, \code{attack\_budget}, which sets the number of swaps as $\mathrm{clamp}(\mathrm{round}(100\cdot\text{budget}),1,8)$; levels 0.01, 0.03, 0.05, 0.08, i.e.\ 1, 3, 5, 8 swaps, on the clean V3 weights, seed 42.
\item \textbf{Safety sweep:} the existing nested weights at rates 0, 0.25, 0.5, 0.75, 1.0, plus the 2-label reference as control; behaviour measured on the severe-marker column with at least 30 severe positives required.
\item \textbf{Monotonicity:} for a signal expected to rise with severity, a \emph{violation} is an adjacent pair in which the higher severity has a strictly lower value; for a score expected to fall, the reverse. Ties are allowed and counted. Spearman $\rho$ is descriptive; there is no pass or fail threshold.
\item \textbf{Repeatability:} each level run twice.
\end{itemize}

\section{Score calibration and held-out evaluation}
The calibration design is described with the mapping (Section~\ref{sec:v4}). Held-out evidence is the fairness confirmation and severity sweeps evidence, re-mapped with the frozen anchors and not re-measured. The check \code{check\_frozen} refuses to run the held-out evaluation if the anchors in code differ from the frozen file (frozen 22:58:31\,UTC, held-out evaluated 22:58:44\,UTC on 2026-10-02). The held-out values were known before the mapping was written, so the check is constrained by the pre-declaration but not blind.

\section{Deterministic versus LLM interpretation}\label{sec:l2m}
Twelve evidence packets (schema \code{l2-evidence-packet-v1}) were built from the controlled models: the 2-label reference, V1, a tampered copy of V1, V2, V3, V4, V4b, V5, V6 and the Safety sweep levels 0.25, 0.75, 1.0, labelled P01 to P12 in that order. A packet holds the card text (model name replaced by the packet id), the artifact verification and, where one exists, the frozen severity sweeps behavioural measurement. Never included: FRIES score, O/S/D, risks, \code{aspect\_scoring}, gates, status, claim verdicts, flags, folder names or defect labels.

The deterministic evaluator recomputes current evidence with the production pure functions and the v3 bands. The LLM evaluator is the production \code{HybridOSDAgent} on a context built from the packet, five independent runs per packet (60 planned). Both record the packet sha256 and the analysis asserts that they match. Derived fields are fixed in advance: LLM ``risk present'' means $O\le5$ (the prompt's own definition); the frozen prompt has no abstain option, so the LLM cannot answer UNCERTAIN. Fairness and Robustness are out of scope because they never reach an LLM. Disagreements are classified into pre-registered categories (insufficient evidence, localisation, evidence interpretation, severity, truncation/fallback). Both outputs are preserved verbatim.

\section{Independent evidence review}\label{sec:l10m}
Twelve single-dimension packets were declared before any packet was built (Table~\ref{tab:l10pk}): a clear defect, a control, a borderline case or an insufficient-evidence case for each of the five dimensions. Packets are shown to evaluators with a whitelist of measured fields only, with plain-English explanations of each measure that say what a number \emph{is} and never what it \emph{means}. Packet hashes are computed before any evaluation. The first leakage test run caught source-file paths (which contain model names) in the packets; we moved them to the reference file before freezing.

\noindent Each reviewer answers five questions per packet: \textbf{Q1} is the evidence sufficient (YES/\allowbreak NO/\allowbreak UNCERTAIN); \textbf{Q2} is there evidence of a meaningful risk; \textbf{Q3} which FRIES dimension; \textbf{Q4} severity from 1 (catastrophic) to 9 (negligible), or N/A; \textbf{Q5} a short rationale. Reviewers were told to work alone, to use only the form, and to enter only an assigned code. The \emph{TrustLens reference answer} for a packet is produced from the same frozen evidence under the current methodology: risk YES iff a risk id was raised or \code{aspect\_scoring} says so, NO when evidence is sufficient and no risk, UNCERTAIN when the evidence is insufficient; severity is $S$. The human study used the v9 reference; the earlier official LLM attempt and the Claude supplement were compared against the v8 reference that existed then.

\textbf{Three evaluator groups, kept separate.} (i) Humans: a Google Form, 12 packets per submission; the analysis script reads the raw export, which is never modified. (ii) The official independent LLM review: separate prompt \code{l10-review-v1-2026-10-03}, providers in order Gemini, Groq, NVIDIA, one attempt each. (iii) A supplementary evaluation in which \emph{Claude} (\code{claude-opus-5-5}) answered the same frozen prompts; hashes were checked against the official run, the answers came from a fresh-context subagent told to read only the exported prompt files (an instruction, not technically enforced), and the orchestrating session wrote none of the answers. Claude is not a human reviewer and its results are never merged with groups (i) or (ii).

\textbf{Comparison.} Per pair: risk agreement, dimension agreement, severity exact and within one (when both give one), sufficiency agreement, Cohen's or Fleiss' $\kappa$ only with at least eight common packets. A disagreement is assigned the first applicable category: provider infrastructure, parser format, abstention mismatch (exactly one side UNCERTAIN on risk), insufficient evidence, localisation, evidence interpretation, severity ($|\Delta S|\ge2$), agree. For the human analysis severity counts as a judgment only when the reviewer answered Q2 = YES, because the form did not enforce N/A.

\section{External Hugging Face validation}\label{sec:extm}
Seven real text-classification models were selected deliberately so that architecture, size, head type, training data, label scope, documentation and language scope vary. The selection (\code{selection.json}) was written before any evaluation, and each model is pinned to an immutable revision SHA that was re-resolved against the Hub. The contract is identical to the controlled suite (same 3\,000-row eval set, Fairness, Robustness and Safety contracts, \code{AI\_AUTONOMOUS}, \code{llm\_v1}); multi-label models use the toxicity head as target. Per-model verification records the final status, that the evaluated revision equals the pin, and that all five probes ran. We report the 2026-10-03 \code{v9r} rerun on the methodology v9 stack (git head \code{0103344}) as the main result; the earlier v8 folder is left untouched.

\section{Statistical treatment}
The study is descriptive: counts, pairwise agreement, kappa and alpha with bootstrap intervals, and Spearman $\rho$ over four or five levels. We run no significance tests: 12 packets, five severity levels and seven models do not support them. Percentile bootstrap CIs use $B=1000$ inside the probes and $B=5000$ over packets for human agreement.
