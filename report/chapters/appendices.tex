\chapter{LLM Prompt and Reviewer Protocol}\label{app:prompts}

Three readings of an evidence packet stay separate. (1) The \emph{LLM comparison} (Section~\ref{sec:l2}) used the production rating prompt on twelve packets, five runs each, through the provider chain fixed in the code: provider A is Gemini (\code{gemini-3.6-flash}, no temperature recorded, provider default), provider B is Groq (\code{openai/gpt-oss-120b}, temperature 0.2) and provider C is NVIDIA NIM (\code{nvidia/nemotron-3-super-120b-a12b} as recorded in the run records, temperature 0.2). The first sessions on 2 October 2026 returned 22 valid answers (A 9, B 13) because of rate limits, daily token limits and a missing endpoint for C. The other 38 planned calls were resolved by resuming the same script with the same prompt and packets (A 6, B 28, C 4 valid answers); the log timestamps put the A and B answers on 28 October 2026 and the four C answers on 3 October 2026. All 60 records are in \code{results/l2\_det\_vs\_llm\_20261029\_r5}, whose log keeps every failed attempt; the earlier incomplete run is kept unchanged in \code{\_r3}. (2) An earlier version of this experiment filled the 38 missing calls with answers from a different model read by a fresh agent (folder \code{\_20261022\_r4}). That set was a different evaluation, is not part of the 60 reported here, and is kept only for audit. (3) The \emph{independent evidence review} (Section~\ref{sec:l10}) used the review prompt and the human form.

\section{O/S/D rating prompt}\label{app:ratingprompt}
The template of the LLM-assisted engine (version \code{osd-llm-v3-decision-first-2026-10-03}; provider-specific sampling settings are described above); \code{\{card\_text\}} is the card cut to 5\,000 characters and \code{\{evidence\_block\}} holds, per dimension, an uncut ``decision'' line (status, risk and gap fields) and ``details'' cut at 3\,000 characters. Only Integrity, Explainability and Safety (card part) are sent. The run records set \code{prompt\_truncated} for 5 of the 60 runs, all on packet P01 (provider B four, provider A one). The cuts are applied by TrustLens when it builds the prompt, before any provider is called; the records do not say which cut applied, but the P01 card has 11\,095 characters, above the 5\,000 limit. These five responses are valid under the output schema but were made on shortened evidence (Section~\ref{sec:l2}). The text is read from the source by \code{report/make\_tables.py}.

\section{Evidence-review prompt}\label{app:reviewprompt}
The official LLM review (identifier \code{l10-review-v1-2026-10-03}) used a much shorter prompt, stored in full in \code{prompts/evidence\_review\_prompt.txt}. It tells the model to judge only the packet shown and that no automated verdict is included, and requires a single JSON object with five fields: \code{risk\_present} (YES, NO or UNCERTAIN), \code{dimension} (one of the five dimensions, NONE or UNCERTAIN), \code{severity} (an integer from 1, catastrophic, to 9, negligible, or null when no risk is present), \code{evidence\_sufficient} (YES, NO or UNCERTAIN) and \code{rationale} (two to four sentences citing the numbers or text that drove the answer). 

\section{Reviewer protocol}\label{app:reviewer}
Human reviewers answered the same five questions for every packet (Table~\ref{tab:appquestions}). They worked alone, used only the form page, entered only a reviewer code and could not edit answers. Each packet opened with a neutral note and explained each measure in words that said what a number \emph{is}, not what it \emph{means}; none stated an acceptable level for any metric.

\section{Reported study versus the current repository}\label{app:trace}
The experiments in this report were run on the research version of the code between 2 and 28 October 2026. The repository has continued to change since, and three of its documents describe different moments. The reproduction guide and this appendix describe the study. The pre-experiment state of the project, in which the default fairness probe fitted a tabular logistic-regression proxy on an Adult Census subset and the Safety probe had no behavioural test, ended before the study: the proxy code was deleted on 10 September 2026, and in the code used here the fairness probe predicts with the imported model through the inference backend and the Safety probe measures the severe false-negative rate on a labelled dataset. The \code{README.md} on the public default branch was not updated to match and still describes the earlier state, so \emph{it should not be used to judge the reported experiments}. The same gap affects reproduction. As checked on 28 October 2026, the default branch holds the experiment scripts and the results of the first runs (up to 3 October) but not the later folders the report uses (the final external-audit rerun, the pooled LLM comparison, the human-review analysis, the severe-miss replay), which are on the project's feature branch \code{feat/ui-shell}. The history of the fairness and Safety probes was read from the repository's commit log and source files, not from the README. Conversely, nothing here should be read as a claim about the current default product behaviour: the default assessment engine proposes no O/S/D ratings, behavioural probes need a user-supplied labelled dataset with a group or severe-subset column, and the heuristic and LLM-assisted engines that produced the reported ratings are opt-in. The reported scoring methods are versions of an experimental prototype, and later code changes (an empty card now abstains from a rating) postdate every experiment.

Table~\ref{tab:trace} links each experiment to its stored results, scripts and recorded version. Where the stored files do not record the code revision of a run, the table says so. The only runs whose results record a git revision are the two external audits (\code{run\_log.json}). For the others, the revision is the commit that first added the results, which is an upper bound on when they were produced and not a record of the code that produced them. Method labels (v3, v4, v9, v10) are those of the version history in the reproduction guide and the identifiers in the repository's \code{methodology\_version} module; the external-audit result files carry per-probe versions and a mapping identifier but not the evaluation-level label, so the attribution of the final audit to the v9 method rests on its recorded git revision.
