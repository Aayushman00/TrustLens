\section{Main suite: per-defect outcomes and dimension profiles}\label{app:suite}
Outcome of each injected defect in the main suite:
\begingroup\sloppy
\begin{itemize}
\item \textbf{Robustness (V2): detected} at score level (accuracy drop 0.041; score 7.56 against 8.65), although \code{R-ROB-PERT} did not fire because the drop was below $\varepsilon_{drop}=0.05$.
\item \textbf{Fairness (V1): not detected} by any rule. EOD was 0.164 against the control's 0.174, and the excess demographic parity was 0.000, because the dataset's own group gap is 0.505. This is a negative result, and it motivated the fairness-rule redesign and fairness confirmation.
\item \textbf{Safety (V5): measured but not separated.} The severe-harm FNR was 0.44 (CI [0.38, 0.50]) against the control's 0.355, but both received Safety 6.60.
\item \textbf{Explainability and Integrity card defects:} the LLM-rated scores were lower (V3 Explainability 4.0; V4 and V4b Integrity 2.3--2.4) than the control (5.2$\pm$1.2 and 4.5$\pm$1.8), but the control's LLM noise kept them under the pre-registered threshold.
\item \textbf{Spillover:} the overfit V2 was also less fair (EOD 0.370). Its Fairness flag counts as a false positive under the pre-registered rule although the effect is real.
\end{itemize}
\endgroup

The Integrity entries show why this layer was hard to read: the 2-label reference (4.54$\pm$1.80) and the compound model (4.23$\pm$2.23) overlap with the ranges of several flawed models, which is the visible cost of LLM-rated noise on a control. The Hub import of the same weights scored 8.65$\pm$0.00. We did not isolate the cause; the import differs from the local copy in having a pinned revision and a Hub file listing, which the v3 Integrity band counted and the local folder lacked (Section~\ref{sec:gaps}).

\section{Reproducing the experiments}\label{app:repro}
Commands are run from \code{backend/\allowbreak } with the project virtual environment; training uses \code{USE\_TF=0}. The Docker stack must be running for the API-based runs (rebuild \code{api} and \code{worker} after backend changes). Seeds and output folders are those named in the corresponding plan.
\begin{lstlisting}
# controlled suite (data, training, evaluation through the API)
python -m app.scripts.prepare_flawed_suite_data
python -m app.scripts.train_flawed_suite --all
python -m app.scripts.run_flawed_suite_eval
python -m app.scripts.repeat_eval            # repeated runs
python -m app.scripts.compare_ground_truth   # apply the frozen rules

# disclosure-gap separation: replay
python -m app.scripts.replay_l3_disclosure_gaps <new_out_dir>

# fairness confirmation run (fresh seed, fresh data)
python -m app.scripts.prepare_flawed_suite_data --fairness-confirm \
    --seed 20261003 --out ../results/fairness_confirm_20261003
python -m app.scripts.train_flawed_suite --fairness-confirm \
    ../results/fairness_confirm_20261003 --seed 20261003
python -m app.scripts.run_fairness_confirm

# severity sweeps
python -m app.scripts.run_defect_severity --out ../results/defect_severity_20261003

# independent review: human analysis (stdlib only, from the repository root)
python results/l10_human_form/analyze_human_responses.py

# external Hub audit
for s in select run profile; do python -m app.scripts.run_external_hub_validation $s; done

# figures and this report
cd report && python make_figures.py && python make_figures_final.py
pdflatex main.tex
\end{lstlisting}
