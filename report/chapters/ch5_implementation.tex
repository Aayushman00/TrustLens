\section{Evidence, reproducibility and error handling}
Source files per component are listed in Table~\ref{tab:impl-status}.

\paragraph{Evidence and reproducibility features.} Each probe stores raw output as a JSON artifact with a SHA-256 hash. Evaluations are stamped with an immutable \code{methodology\_version}. Model revisions are frozen at draft time and the loaded snapshot is checked against them (\code{model\_snapshot\_check.py}). Probes take an explicit seed. The Civil Comments dataset is pinned to revision \code{f2970eb3\ldots} in \code{prepare\_flawed\_suite\_data.py}. Evaluation datasets are content-addressed, so two evaluations that name the same data really use the same bytes.

\paragraph{Error handling.} Probe outputs that violate the contract raise \code{ProbeError} and fail the evaluation instead of being stored. A probe that cannot run records a status (\code{INSUFFICIENT\_EVIDENCE}, \code{SKIPPED}, \code{NOT\_APPLICABLE}, \code{FAILED}, \code{PROXY}). LLM failures never fail the evaluation: the heuristic numbers are kept and each aspect stores \code{llm\_fallback\_reason}, \code{llm\_attempts} and \code{llm\_prompt\_version}. Those three fields exist because in the first final suite we had 11 fallbacks out of 45 runs and could not tell afterwards why; the information was only in container logs.

The human-review analysis (\code{results/\allowbreak l10\_human\_form/\allowbreak analyze\_human\_responses.py}) is a stdlib-only script that reads the raw form export, the frozen reference and the packet mapping, and writes the REPORT, per-response and per-packet tables. We re-ran it from the raw export while writing this report and it reproduced the committed output byte for byte.

\section{Installation and execution}
The commands below come from the repository (\code{README.md}, \code{scripts/\allowbreak }, \code{Makefile}). Prerequisites: Python 3.11+, Node 18+, Docker Desktop with Compose v2; an NVIDIA GPU is optional but used when present.

\begin{lstlisting}
# one-time backend setup (Windows PowerShell)
.\scripts\setup-local-dev.ps1
.\.venv\Scripts\Activate.ps1
docker compose up -d postgres redis
cd backend; alembic upgrade head
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
# in other terminals: worker and frontend
.\scripts\dev-worker.ps1      # Celery worker
.\scripts\dev-frontend.ps1    # React dashboard (npm run dev)
# tests
cd backend; python -m pytest -q
\end{lstlisting}

A user works through the dashboard (Figure~\ref{fig:ui}): import a model, create a draft, attach a dataset with label mapping and sensitive column, confirm, and read the report. It shows the five dimensions with their evidence and O/S/D source, the confidence, and a disclosure of mode, engine and whether a human reviewed the numbers. Appendix~\ref{app:repro} gives the experiment commands.
