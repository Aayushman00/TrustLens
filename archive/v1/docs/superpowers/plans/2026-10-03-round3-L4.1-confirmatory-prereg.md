# L4.1 confirmatory fairness experiment — pre-registration (2026-10-03)

**Status: FROZEN** at the commit "freeze L4.1 confirmatory fairness setup", which adds
the `--seed`/`--out` code below. No new data had been generated, no model trained and no
evaluation run when it was frozen. Results are reported against this version. The
"Frozen additions" section was written at freezing time, before any data existed.

## Why a fresh setup

The L4.1 metric (EOD) was chosen after inspecting the stored 2026-10-02 suite (see
`2026-10-03-round3-L4.1-eod-fairness-risk.md`). That suite, together with its eval set,
models and runs, is therefore **exploratory evidence only**. A confirmatory test needs:
- data that was not inspected,
- models trained under a new seed,
- the rule fixed as it is now.

## Frozen rule under test

The rule is `v6-eod-fairness-risk-2026` / `tl-fairness-binary-v1.2`, with risk id
`F-FAIR-EOPP`, exactly as implemented at the commit that adds this file:
- **Trigger:** EOD = max_g TPR_g − min_g TPR_g over groups with n ≥ `min_group_n`
  (contract value 30), each with ≥ 1 positive label.
- **CI:** bootstrap percentile 95% CI with B = 1000 and contract seed 42.
- **Risk condition:** FAIRNESS_RISK iff EOD > 0.02 and CI lower > 0.02.
- **Width gate:** G-FAIR-CI-WIDE if the EOD CI width is > 0.15.

The evidence-level detection rule in `results/flawed_model_suite/ground_truth.json` is
also unchanged.

## Fresh setup

| item | value |
|---|---|
| Data seed | `20261003` (new; the suite used 42) |
| Eval set | 3,000 rows from `google/civil_comments` test split, built by the same procedure as `prepare_flawed_suite_data._build_eval_set`: 20% toxic, toxicity ≥ 0.5, identity/severe thresholds 0.0001 as in the suite's `eval_set_manifest.json` |
| Disjointness | Exclude every row whose `text` exactly matches a row of the existing `results/flawed_model_suite/data/eval_set.jsonl` or any `*_train.jsonl` there |
| Train slice | 8,000 rows from the train split with seed `20261003`, disjoint by exact text from all existing train slices and from the new eval set |
| Models | **clean control:** no flip. **Fairness levels:** identity-conditioned 0 → 1 flips at rates 0.2, 0.4, 0.7, 1.0, nested (lower rate ⊂ higher), same flip logic as the suite. Hyperparameters: 3 epochs, lr 2e-5, bs 16, wd 0.01, training seed `20261003` |
| External control | `reference_toxicbert_2label`, using the existing weights unchanged, evaluated on the new eval set |
| Runs | 3 per model. Fairness evidence is deterministic, so runs check repeatability, not variance |
| Outputs | New directories only, e.g. `results/fairness_confirm_20261003/{data,models,runs,analysis}`. No existing result folder is touched |
| Ground truth | A new `ground_truth.json` in that directory, written before training. Clean control and reference: `injected_defects=[]`, `controls` = both. Flip models: `["FAIRNESS"]`, with their rates |

## Hypotheses and analysis (descriptive; no thresholds change after data are seen)

| ID | Hypothesis | Measure |
|---|---|---|
| H1 | No clean control is flagged | FAIRNESS control flag rate = 0 under the frozen evidence-level rule |
| H2 | The flip models at rates ≥ 0.4 are flagged | FAIRNESS evidence-level recall over those models |
| H3 | EOD increases with flip rate | Spearman ρ(rate, EOD) over the 5 levels (0, 0.2, 0.4, 0.7, 1.0) |
| H4 | The gate behaves | Count of INSUFFICIENT_EVIDENCE / `mapping_blocked` per model, reported as-is |

- **Reporting:** all of DPD, `excess_dpd_v1`, EOD, the FPR gap, CIs and group positive
  counts are reported for every model, whatever the outcome.
- **If a hypothesis fails:** the rule stays as it is and the failure is reported. Any
  change becomes a new methodology version with a new pre-registration and fresh data.

## Code (added in the freezing commit)

- Data: `python -m app.scripts.prepare_flawed_suite_data --fairness-confirm --seed 20261003
  --out ../results/fairness_confirm_20261003`. Writes `data/` and `ground_truth.json`
  before any training. It refuses an `--out` inside `results/flawed_model_suite` or a
  non-empty directory, and refuses (rather than shrinks) a slice that the disjointness
  filter leaves short.
- Training: `python -m app.scripts.train_flawed_suite --fairness-confirm
  ../results/fairness_confirm_20261003 --seed 20261003`. The seed is required, models go
  to `<root>/models`, and existing weights are never overwritten.

## Frozen additions (written at freezing time, before any data)

- **Run driver.** The fairness evidence is produced in-process by the production
  `FairnessProbe` (binary path, the code under test). It uses the real `LocalHFBackend`
  for inference on the new eval CSV, with an in-memory content-addressed dataset store,
  under a contract equal to the one `run_flawed_suite_eval` submits (`sensitive_column
  = identity_ref`, `min_group_n = 30`, label `0 -> 0`, `1 -> 1`, positive index 1).
  This avoids two things: the LLM O/S/D stage, which the hypotheses do not use, and the
  running docker worker, which predates L4.1. The FAIRNESS dimension score (O/S/D) is
  therefore not produced. The hypotheses are all evidence-level.
- **Decision criteria.**
  - H1 holds iff neither control (`clean_control`, `reference_toxicbert_2label`) is
    flagged by `evidence_flag_one("FAIRNESS", ...)` in a majority of its runs.
  - H2 holds iff all of `fairness_r040`, `fairness_r070` and `fairness_r100` are
    flagged. Recall over the three is reported either way. `fairness_r020` is reported
    but is not part of H2.
  - H3 holds iff Spearman ρ(rate, EOD) > 0 over the five levels (clean_control as
    rate 0). ρ and the count of adjacent-level decreases are reported. ρ = 1 is called
    "strictly monotone".
  - H4 is descriptive. It has no pass/fail.
- **Repeatability.** Three runs per model. Any run-to-run difference in EOD or the
  finding is reported, not averaged away.
